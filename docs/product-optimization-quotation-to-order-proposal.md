# 报价详情页优化方案：转订单确认流

## 状态

- 当前状态：`正式转单确认流 V1 已接入，待验收`
- 对应主线文档：
  - `docs/product-optimization-master-plan.md`
- 当前正式验收网址：
  - `http://127.0.0.1:3202/quotations`
- 当前验收路径：
  - 进入任一报价详情页
  - 点击右上角 `转单确认`

## 原问题

- 旧版 `转为订单` 会直接创建订单并跳转。
- 用户在建单前没有机会确认：
  - 这张报价能不能转
  - 有没有审批风险
  - 收货信息和仓库要不要先补
- 这会让“报价转单”看起来像一个技术动作，而不是一个业务确认动作。

## 已确认方案

- 把直接转单，改成先进入确认抽屉。
- 第一版只补最必要信息，不重做完整订单表单。
- 已有关联订单时，不允许重复创建。
- 导出审批只做提醒，不做硬拦截。

## 已落地内容

### 1. 顶部主按钮已改成 `转单确认`

- 入口仍保留在报价详情页右上角。
- 如果该报价已经关联订单，按钮直接变成 `查看订单`。

### 2. 已接入右侧确认抽屉

- 抽屉内容分为三段：
  - 转单摘要
  - 转单判断
  - 转单补充信息

### 3. 已实现的轻度拦截规则

- 已有关联订单：拦截
- 折扣审批待处理：拦截
- 报价已驳回：拦截
- 报价无品项明细：拦截

### 4. 已实现的提醒规则

- 导出审批待处理：提醒，不拦截
- 存在低于建议价品项：提醒，不拦截

### 5. 第一版补充字段

- 下单时间
- 收货人
- 联系电话
- 收货地址
- 仓库
- 备注

备注默认值：

- `由报价 {quotationNo} 转入`

### 6. 页面已补的承接信息

- 报价详情页右侧状态卡新增：
  - `关联订单`
- 右侧快捷操作卡也保留转单入口，避免用户只在顶部找按钮。

## 当前实现范围边界

- 这次没有重做订单中心的新建订单流程。
- 这次没有扩展渠道商、运费、折扣等完整建单项。
- 这次只把“报价转单”这一步做成专业、可确认、可控的流程。

## 当前相关代码位置

- 报价详情页：
  - `apps/web/app/(dashboard)/quotations/[id]/page.tsx`
- 现有订单创建接口：
  - `apps/web/lib/orders.ts`

## 下一步验收重点

- 抽屉打开时，是否比旧版直接建单更稳
- 拦截项和提醒项是否符合业务直觉
- 补充字段是否够用且不多余
- 成功创建后跳转到订单详情是否顺畅
