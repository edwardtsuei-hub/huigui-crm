# 客户销售表格导入评估

日期：2026-04-17

## 结论

当前 CRM 可以先承接第一批客户资料导入，范围建议限定为：

- `客户合作跟进表.xlsx`
  - `合作资源`
  - `新增资源`

这两张表可以直接落到现有 CRM 的：

- `Customer`
- `CustomerFollowup`

其余三张表建议先做归档保存，不建议直接结构化导入到当前 CRM 主数据中。

## 需要新增功能后再结构化导入的内容

### 1. 销售订单与收款

下列资料当前没有正式数据结构：

- 购买产品
- 规格/数量
- 实收金额
- 应付金额
- 单价
- 利润
- 收款情况
- 订单号
- 发货仓库
- 发货快递

建议新增：

- 销售订单模块
- 收款/对账模块
- 发货与物流模块

### 2. 试验示范点项目管理

下列资料当前没有正式数据结构：

- 试验基地
- 试验对象/作物
- 试验面积
- 分次喷洒日期
- 使用过程反馈
- 采收日期
- 种植周期

建议新增：

- 试验项目模块
- 阶段记录与反馈模块
- 项目关联客户/产品/图片资料模块

### 3. 客户多联系人与客户画像

当前 CRM 只有单一联系人字段，不适合完整承接：

- 多个负责人
- 农场负责人 + 对接人并存
- 家庭/公司/农场身份
- 种植面积
- 种植作物
- 过往种植方式

建议新增：

- 客户联系人子表
- 农业客户画像字段组

## 四份 Excel 的建议处理方式

### A. 客户合作跟进表.xlsx

建议：立即导入

导入目标：

- 客户主档
- 跟进记录

### B. 海能量购买客户明细表.xlsx

建议：第二批导入，且只导入“客户 + 购买背景摘要”

可先简化承接：

- 客户名称
- 收件地址
- 用途身份（家庭/公司/农场）
- 购买日期
- 购买目的
- 使用问题跟进

不建议当前直接作为订单导入：

- 购买元素
- 规格/数量
- 付款金额

当前映射策略：

- 客户名称、手机、城市、地址 → `Customer`
- 购买目的、使用跟进、种植面积、作物 → `cooperationDirection` / `cooperationContent`
- 过往种植方式、种植问题、客户类型 → `remark`
- 购买背景摘要 → `CustomerFollowup`

说明：

- 这些内容会在 CRM 中保留，但目前仍属于客户背景与跟进摘要
- 还不会形成正式订单、收款、发货、产品明细子表

### C. 海能量农业工业客戶登记总表（对内）.xlsx

建议：暂不结构化导入，只做资料归档

原因：

- 主要是订单、收款、发货、利润视角
- 现有 CRM 没有对应正式业务对象

当前拆解结果：

1. `海能量农业元素 登记`

- 本质是订单主表 + 订单明细
- 已识别订单组数：30
- 每个订单号下会有多行产品明细
- 同一订单只有首行保留下单日期、收件人、实收金额等头信息，后续行是商品明细续行

可识别字段：

- 下单日期
- 收件人
- 收货地址
- 联系电话
- 订单号
- 发货仓库
- 发货快递
- 实收金额 / 应付金额
- 产品
- 数量
- 使用用途

结论：

- 这部分不适合直接塞进 `Customer` / `CustomerFollowup`
- 如果强行导入，只能退化成“客户备注”，会丢掉订单号、明细行、金额和发货结构

2. `填写示例`

- 本质是分销 / 商家结算明细
- 有效结算行：5

可识别字段：

- 下单日期
- 产品名称
- 数量
- 商家名称
- 供货价
- 现结货款
- 收款情况
- 成本单价
- 成本金额
- 利润金额
- 备注（折扣规则）

结论：

- 这部分属于“渠道结算 / 利润核算”
- 不应该进入客户 CRM 主档
- 需要独立的分销结算模块

详细数据结构设计见：

- [order-payment-shipping-settlement-design-2026-04-17.md](/Users/i-datsuei/Desktop/Huigui CRM & Quotation System/docs/imports/order-payment-shipping-settlement-design-2026-04-17.md)

3. `收款信息`

- 本质是收款账户说明，不是业务记录
- 当前只有 1 条配置型说明

结论：

- 适合放到系统设置 / 财务账户配置
- 不适合导入客户或订单记录

如果只基于当前 CRM 硬要保留，建议最低限度处理为：

- 原始工作簿上传到档案中心归档
- 如有明显新客户，可补建 `Customer`
- 订单、结算、收款信息本身不做结构化入库

后续推荐模块拆分：

- 销售订单主表：订单号、客户、下单日期、收货信息、总金额、应付金额、用途、状态
- 销售订单明细表：订单、产品、数量、单价、小计
- 发货记录表：订单、仓库、快递、物流单号、发货时间
- 收款记录表：订单、收款金额、收款方式、收款时间、备注
- 渠道结算表：商家、产品、供货价、成本、利润、收款情况
- 财务账户配置：收款账户、开户行、主体公司、适用场景

### D. 海能量试验示范点明细表.xlsx

建议：暂不结构化导入，只做资料归档

原因：

- 主要是试验项目与过程记录
- 现有 CRM 缺少试验项目主表与阶段反馈表

当前拆解结果：

- 当前工作簿只有 1 个有效 sheet
- 每一行不是单纯客户资料，而是一条“试验项目”
- 同一个基地可能会有多条不同试验项目
  - 例如：`潍坊市前阙村` 同时存在“西红柿/大樱桃试验”和“鹌鹑粪便试验”

主要字段分层如下：

### 1. 可复用到现有客户主档的字段

这些字段可以作为客户基础信息来源，但不能单独代表一个试验项目：

- 农场/基地名称
- 公司全称
- 所在地
- 详细收件地址
- 农场/项目负责人
- 对接人

建议映射：

- 客户名称 / 公司名称
- 城市 / 地址
- 联系人（当前只能保留一个主联系人，其他负责人仍会丢失）

### 2. 可部分借用现有农业方案字段的内容

现有 `AgriculturePlan` 更偏“报价与桶数计算”，只能部分复用：

- 作物名称
- 作物类别
- 试验面积
- 种植/试验开始日期
- 种植周期

但当前农业方案模块缺少：

- 基地维度
- 试验目的
- 物资分配
- 多次喷洒记录
- 过程反馈
- 采收结果

结论：

- 现有农业方案模块不能直接替代试验示范点模块
- 最多只能作为后续“从试验转正式农业方案报价”的下游对象

### 3. 必须单独建模的试验项目字段

这些是试验项目的核心，不适合放进客户备注或农业方案备注：

- 试验实施原因及目的
- 农场规模/占地面积
- 试验对象
- 海能量物资分配总量
- 采收日期
- 初次喷洒日期
- 2次喷洒日期
- 3次喷洒日期
- 4次喷洒日期
- 使用过程反馈

### 推荐模块拆分

1. 试验项目主表

建议字段：

- 项目名称
- 客户 / 基地
- 公司名称
- 所在地
- 地址
- 主负责人
- 对接人
- 基地规模
- 试验对象
- 作物类别
- 作物名称
- 试验面积
- 试验目的
- 项目状态
- 开始日期
- 预计采收日期
- 实际采收日期
- 周期说明

2. 试验用料记录表

建议字段：

- 项目
- 物资名称
- 分配总量
- 发放日期
- 备注

3. 试验阶段记录表

建议字段：

- 项目
- 阶段类型
  - 初次喷洒
  - 第2次喷洒
  - 第3次喷洒
  - 第4次喷洒
  - 观察记录
  - 采收反馈
- 日期
- 内容
- 图片/附件

4. 试验结果反馈表

建议字段：

- 项目
- 当前结果
- 差异观察
- 口感/品质反馈
- 产量反馈
- 问题记录
- 下一步建议

### 如果暂时不开发模块，最低限度建议

- 先把原始 Excel 上传到档案中心归档
- 只提炼客户主档到 CRM
- 试验项目本身先不做结构化导入
- 如需查询，先在档案中心通过标签或资料夹管理
