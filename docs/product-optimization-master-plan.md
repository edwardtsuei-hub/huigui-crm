# 产品优化主线与续接说明

## 文档目的

- 这份文档是当前项目产品优化工作的主入口。
- 以后如果对话中断、换新线程或需要重新接手，优先先读这份文档，再继续执行。
- 这份文档会持续记录：
  - 优化总目标
  - 优先级
  - 协作规则
  - 当前做到哪里
  - 下一步该提什么方案
  - 每一页的状态

## 协作规则

### 1. 先出方案，再执行改动

- 从现在开始，所有页面级优化都按以下顺序进行：
  1. 我先给出该页的优化方案
  2. 你确认方案
  3. 我再开始实现
  4. 实现完成后，把变动记录回这份文档

- 这里的“页面级优化”包括：
  - 页面结构调整
  - 核心交互改动
  - 组件层级重排
  - 关键文案方向调整
  - 信息架构变化

### 2. 没有确认，不直接改页面设计

- 即使我已经判断该方案优先级很高，也不会直接改页面设计。
- 我会先把：
  - 目标
  - 问题判断
  - 改法
  - 影响范围
  - 验收方式
  提给你确认后再执行。

### 3. 每次实现后必须回写记录

- 每做完一个页面或一个全局模块，就要回写：
  - 改了什么
  - 为什么这么改
  - 涉及哪些页面
  - 当前状态
  - 下一步是什么

### 4. 新对话续接方式

- 以后如果重新开对话，可以直接让我先读取：
  - `docs/product-optimization-master-plan.md`

- 然后继续以下动作：
  - 查看“当前执行顺序”
  - 查看“页面状态总表”
  - 查看“最近一次更新”
  - 从“待你确认”的那一项继续

### 5. 以后所有测试页都必须附带网址

- 只要我提供测试页、预览页、验证页，就必须同时给出：
  - 可直接访问的网址
  - 对应的预览路由

- 默认输出方式：
  - 先给可点击网址
  - 再说明这是测试页还是正式页

- 这条规则从 `2026-04-21` 起固定执行，不再遗漏。

### 6. 项目收尾前必须做一轮全站页面瘦身

- 在这一轮主要开发接近收尾时，要对全部正式页面再做一次统一优化。
- 这轮优化的重点不是补功能，而是把页面里用户没有必要了解的文字、重复说明、开发视角提示和过度引导收掉。
- 验收标准是：
  - 页面更干净
  - 用户更快看到真正要做的动作
  - 不让页面像“说明书”或“调试面板”
  - 只保留会影响判断、操作和结果反馈的必要信息
- 这条要求视为固定收尾项，后续即使换新线程继续开发，也要在最终验收前执行。

## 当前优化总目标

- 把系统从“模块已经齐了”推进到“团队高频使用时也顺手、稳定、清楚”。

### 当前主判断

- 当前系统的主要问题已经不是缺页面，而是：
  - 高优先级动作虽然能做，但还不够快
  - 跨模块闭环虽然存在，但还不够稳
  - 批量处理和管理动作虽然开始出现，但还不够强

## 总优先级

### P0

1. 全局搜索升级成真实业务搜索
2. 报价转订单改成确认式转单
3. 检测待补关联支持批量处理
4. 报价中心补齐批量动作
5. 订单中心补齐批量动作
6. 行业 / 服务 / 养殖报价做业务化分层

### P1

1. 客户池治理：去重、合并、超时跟进、负责人负载
2. 产品 AI 解析升级：置信度、冲突对照、待确认队列
3. 档案自动归档与业务回链
4. 工作管理团队闭环：一键催交、差异视图、派生待办
5. 通知 / 日程增加处理动作
6. 角色权限变更安全性增强

### P2

1. 首页个性化
2. 经营分析看板
3. 自动化提醒策略
4. 移动端和窄屏适配收口
