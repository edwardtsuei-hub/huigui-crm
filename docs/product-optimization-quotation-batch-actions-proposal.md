# 报价中心优化方案：批量动作

## 状态

- 当前状态：`正式批量动作 V1 已接入，待验收`
- 对应主线文档：
  - `docs/product-optimization-master-plan.md`
- 当前正式页网址：
  - `http://127.0.0.1:3202/quotations`

## 当前问题

- 报价中心现在已经能把重点队列浮出来，但本质上仍偏向“看板”而不是“处理台”。
- 当前主列表只有选中和查看详情，没有批量动作入口。
- 真正的审批动作还留在单笔详情页，导致主管处理一批报价时需要来回进入详情，效率不够高。
- `待审批` 队列还混入 `已驳回` 记录，容易让“待处理动作”和“待回改结果”混在一起。

## 代码现状判断

- 当前前端主页面：
  - `apps/web/components/quotations/QuotationsWorkbench.tsx`
- 当前列表数据来源：
  - `GET /quotations`
- 当前可用动作接口：
  - `POST /quotations/:id/review-approval`
- 当前后端只有单笔审批接口，没有批量审批接口：
  - `apps/api/src/quotations/quotations.controller.ts`
  - `apps/api/src/quotations/quotations.service.ts`

## 建议的第一版方案

### 1. 保留当前页面结构，不重做整页

- 继续保留：
  - 顶部经营信号
  - 中间队列列表
  - 右侧单笔检视面
- 第一版只补“批量动作”，不重做信息架构。

### 2. 只在可处理队列开启批量模式

- `待金额审批` 队列：
  - 支持批量通过
  - 支持批量驳回
- `待导出放行` 队列：
  - 支持批量通过
  - 支持批量驳回
- `最近新增` 队列：
  - 第一版不做批量动作

### 3. 每条报价增加勾选能力

- 仅对当前队列里真正可处理的 `PENDING` 记录开放勾选。
- `REJECTED` 记录仍可见，但不进入批量处理选择，避免误操作。
- 支持：
  - 全选当前队列
  - 清空已选

### 4. 增加顶部批量操作条

- 工具条显示：
  - 已选数量
  - 当前批量动作类型
  - `批量通过`
  - `批量驳回`
  - `退出批量`
- 当选择 `批量驳回` 时，统一弹出一个简短驳回原因输入框，作为本次批量备注。

### 5. 提交方式采用低风险 V1

- 不新增后端批量接口。
- 前端沿用现有单笔接口逐条提交：
  - `POST /quotations/:id/review-approval`
- 页面反馈：
  - 处理中 x/y
  - 成功数
  - 失败数
  - 失败项保留，方便重试

## 我建议先不做的内容

- 不做批量导出 PDF
- 不做批量外发客户
- 不做跨队列混合批量处理
- 不在第一版里拆出新的“已驳回待修改”独立页面

## 这样安排的原因

- 这页最核心的效率问题，不是“看不到”，而是“看到了却还得逐笔进去处理”。
- 现有后端已经有单笔审批能力，先顺着现有接口做批量提交流，交付最快、风险最低。
- 如果第一版直接上真正批量接口、批量导出、批量外发，范围会明显膨胀。

## 已落地内容

### 1. 已在正式页加入批量模式入口

- 当前仅 `待金额审批 / 待导出放行` 两个队列会出现 `开启批量处理`。
- `最近新增` 队列保持查看用途，不混入批量动作。

### 2. 已支持主列表勾选与队列级批量处理

- 支持：
  - 勾选单条报价
  - 全选当前队列
  - 清空已选
- `待金额审批` 队列中的 `已驳回` 记录保留可见，但不会进入批量误选。

### 3. 已接入批量通过 / 批量驳回

- 主列表即可直接处理：
  - `批量通过`
  - `批量驳回`
- 批量驳回支持统一备注，用于一次性说明驳回原因。

### 4. 已补提交流程反馈

- 批量处理时会显示：
  - `处理中 x/y`
  - 成功数
  - 失败数
- 失败项会保留在已选列表里，方便直接重试。

## 当前实现范围边界

- 这次没有做批量导出 PDF。
- 这次没有做批量外发客户。
- 这次没有新增真正的后端批量审批接口。
- 这次没有拆出单独的“已驳回待回改”新页面。

## 当前相关代码位置

- 页面逻辑：
  - `apps/web/components/quotations/QuotationsWorkbench.tsx`
- 样式：
  - `apps/web/components/quotations/QuotationsWorkbench.module.css`

## 下一步验收重点

- 批量入口是否足够自然，不打断原本看板阅读
- 批量通过 / 驳回是否比旧版逐条进详情明显更快
- `已驳回可见但不可误选` 是否符合你们主管处理习惯
- 批量备注、进度反馈、失败重试是否够用
