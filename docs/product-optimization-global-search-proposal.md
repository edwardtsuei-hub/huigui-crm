#### 3. 搜索框仍放在原建议位置

- 放在顶栏右侧操作区：

#### 4. 搜索结果改为更克制的下拉层

- 结果不再做成厚重的大卡片拼盘。
- 改成更像真实产品里的紧凑下拉层：
  - 宽度接近搜索框本身
  - 结果项高度更紧凑
  - 减少彩色块和大面积背景

#### 5. 分组保留，但弱化

- 仍保留分组逻辑：
  - 客户
  - 报价
  - 订单
  - 检测
  - 成员

- 但视觉上改成更轻的组标题，不做大块分区。

#### 6. 页面主体只保留真实业务骨架

- 主体区不再讲设计理念。
- 改为客户详情页骨架，例如：
  - 页面标题

这样用户会自然把注意力放到：

- 下拉结果是否压住重要操作

## 为什么先做这一项

- 这是当前第一优先级里最适合先启动的一项。
- 它不属于单一页面，但会影响所有页面的使用效率。
- 现在系统已有大量真实业务对象，如果搜索仍只搜“工作台入口”，系统会越来越像很多页面的集合，而不是统一工作台。

## 当前问题

### 1. 只能搜入口，不能搜真实业务对象

- 当前顶部搜索本质上是导航目录过滤。
- 输入真实客户名、报价单号、订单号时，用户得不到真正想找的对象。

### 2. 结果语义不对

- 用户想找的是“客户 / 报价 / 订单 / 检测”，不是“某个菜单入口”。
- 现在空结果提示也偏向“没有工作台入口”，不符合业务场景。

### 3. 它会拖慢所有后续动作

- 找客户慢，后面跟进就慢。
- 找报价慢，后面审批、导出、转订单就慢。
- 找检测慢，后面补关联、回看报告就慢。

## 这次方案想达到的目标

1. 搜索客户、报价、订单、检测、成员时，能直接返回真实对象
2. 用户可以从搜索结果一键进入详情页
3. 结果要按对象类型分组，避免和菜单入口混在一起
4. 权限必须生效，用户只能搜到自己有权查看的对象
5. 现有工作台入口搜索能力保留，但退到次级结果

## 第一版建议范围

### 纳入搜索的对象

- 客户
- 报价
- 订单
- 检测单
- 成员
- 工作台入口

### 暂不纳入第一版的对象

- 档案文件
- 周报 / 月目标
- 审计日志
- 通知内容全文

原因：

- 第一版先把最常查、最能缩短业务路径的对象做好。
- 其他对象可在后续第二轮再加，避免首版范围过大。

## 页面与交互方案

### 方案 A：保留顶部现有入口，升级结果面板

这是我建议的实现方式。

#### 交互结构

- 用户点击或聚焦顶部搜索框
- 输入关键词后，展开结果面板
- 面板按类型分组显示：
  - 客户
  - 报价
  - 订单
  - 检测
  - 成员
  - 工作台入口

#### 每条结果展示字段

- 主标题
  - 例如客户名、报价单号、订单号
- 类型标签
  - 客户 / 报价 / 订单 / 检测 / 成员 / 入口
- 辅助信息
  - 客户：联系人 / 公司 / 地区
  - 报价：客户名 / 状态 / 金额
  - 订单：客户名 / 状态 / 应收
  - 检测：标题 / 机构 / 状态
  - 成员：姓名 / 角色 / 部门

#### 快捷行为

- 点击结果：进入详情页
- 回车：
  - 优先进入最佳业务对象结果
  - 如果没有业务对象，再进入最佳入口结果

#### 空结果文案

- 改为：
  - `没有找到匹配的业务对象或工作台入口。`

### 为什么不建议第一版做成全屏 Command Palette

- 目前系统的主要问题不是“入口不酷”，而是“结果不对”。
- 先把正确结果和跳转链路做稳，比做成大弹窗更有价值。
- 后续如果确认高频使用，再升级成更完整的 command palette 也不晚。

## 搜索逻辑建议

### 排序优先级

1. 编号精确命中
   - 报价单号 / 订单号 / 检测单号
2. 标题或名称命中
   - 客户名 / 成员名 / 检测标题
3. 辅助信息命中
   - 公司名 / 联系人 / 部门 / 地区
4. 工作台入口命中

### 权限规则

- 搜索结果必须走现有权限体系
- 普通角色只能看到自己有权访问的客户、报价、订单、检测、成员
- 管理类结果只对有权限的用户展示

## 技术实现方向

### 前端

- 保留现有顶部搜索 UI
- 将当前基于 `searchCatalog` 的过滤模式，改为：
  - 输入后请求统一搜索接口
  - 返回分组结果
  - 结果面板支持对象跳转

### 后端

- 新增统一搜索接口，例如：
  - `GET /api/search/global?keyword=...`
- 由后端统一聚合：
  - 客户
  - 报价
  - 订单
  - 检测
  - 成员
- 返回统一结构，前端不用自己拼多模块查询

## 对现有页面的影响

### 会影响

- 所有带顶栏搜索的页面
- 顶栏搜索弹层的交互

### 不会影响

- 现有业务详情页结构
- 左侧导航结构
- 快捷创建逻辑
- 首页通知抽屉逻辑

## 这一版不做什么

- 不做全文检索
- 不做模糊拼音搜索增强
- 不做搜索历史和最近访问
- 不做文件内容搜索
- 不做全屏快捷命令系统

这些都可以放到第二轮。
