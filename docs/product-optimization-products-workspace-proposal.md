## 当前状态

- 产品页实际上已经不是“未开始”。
- 当前代码里已经有一整条产品链路：
  - `产品中心`
  - `新增产品`
  - `编辑产品`
  - `产品详情`
  - `AI 解析辅助预览`
- 当前正式页已经体现的方向：
  - 产品中心回到 `资产列表 + 筛选 + 右侧摘要`
  - AI 解析器退到 `新建 / 编辑` 页顶部作为辅助入口
  - AI 解析结果开始进入 `待确认队列`
  - 产品详情页开始承接 `引用记录 / 检测 / 协作摘要`
- 当前还没收口的，不是有没有页面，而是：
  - 方案文档没回写
  - 主线状态没同步
  - 产品中心、解析器、详情页还没被明确描述成一条连续流程

## 当前判断

- 产品页这次不建议推倒重来。
- 更适合的方向不是把产品页做成“说明型大卡片”，而是继续强化成：
  - `产品资产盘点台`
  - `解析辅助录入流`
  - `引用 / 检测 / 协作摘要页`

- 当前我更倾向于把产品线拆成三层职责：
  - `产品中心`：看有哪些产品、能不能报价、资料完整不完整
  - `新建 / 编辑`：把标签图、文本和结构化字段沉淀进主档
  - `详情页`：回看这条产品最近被谁引用、做过哪些检测、还有哪些协作动作

- 这比把所有内容重新塞回一个页面更稳，也更接近业务真实使用顺序。

## 当前问题

### 1. 主线文档对产品页的判断已经落后于真实代码

- 当前主线文档里仍写着：
  - `产品页 | 未开始 | 后续提方案`
- 但代码里其实已经有：
  - 正式产品中心
  - 正式新增 / 编辑 / 详情
  - 多个产品相关预览页

- 这会导致后续接手时误判优先级和真实起点。

### 2. 产品中心、解析器、详情页已经存在，但还没有被定义成一条连续流程

- 当前如果单看每个页面，其实都已经有方向。
- 但从产品优化主线来看，还没有一句清楚的话说明：
  - 先在哪看产品池
  - 再在哪吸收标签与文本
  - 最后在哪回看引用与检测

- 所以产品线当前更像“几个页面都做了”，还不像“一个流程已经成形”。

### 3. AI 解析辅助已经有置信度和冲突对照，但还没进入待确认队列阶段

- 当前解析器已经具备：
  - 文本 / 图片混合输入
  - 置信度提示
  - 冲突候选值对照
  - 写回正式表单前确认

- 但主目标里提到的：
  - `待确认队列`
- 现在还没有正式落位。
- 这个缺口现已在当前轮补上第一版正式入口。
- 当前阶段判断调整为：
  - `解析辅助 V1 + 待确认队列 V1`
- 还没有进入的，仍是：
  - `解析工作台 V2`
  - `批量维护和回填`

### 4. 产品中心已经回到资产视角，但治理口径还不够明确

- 当前产品中心已经有：
  - 搜索
  - 行业筛选
  - 状态筛选
  - 焦点切片
  - 模板汇总

- 但下一步如果继续强化，应该更明确回答这些问题：
  - 哪些产品资料待补
  - 哪些产品可直接报价
  - 哪些产品模板还不稳定
  - 哪些产品解析过但还没正式确认

### 5. 详情页方向是对的，但仍属于轻量摘要层

- 现在详情页已经能看：
  - 基础档案
  - 文案与展示资料
  - 报价规则
  - 最近引用
  - 关联检测
  - 本地协作事项

- 这条方向是对的。
- 但它当前还是“摘要页”，还没有进入：
  - 附件版本历史
  - 审计日志
  - 解析结果回看历史

- 所以这轮更适合先确认定位，不急着继续做重。

## 方案目标

- 让产品页从“页面已经有了”升级成“产品资产流程已经清楚”。
- 这一版核心不是增加更多视觉块，而是让业务在 10 秒内回答这几件事：
  - 现在有哪些产品资产
  - 哪些产品能直接进入报价
  - 哪些产品资料还不完整
  - 某条产品最近有没有被正式引用
  - 某条产品有没有关联检测和协作待办

## 建议方案 V1

### 一、产品中心继续保留“资产盘点台”骨架

- 当前产品中心方向建议保留：
  - 顶部指标
  - 搜索与筛选
  - 高密度资产列表
  - 右侧摘要卡

- 不建议改回：
  - 大卡片浏览页
  - 解析器占据首页主视觉
  - 说明型产品陈列页

- 原因：
  - 产品页在这个系统里更像资产主档，而不是营销展示页。
  - 第一优先级应该是盘点、筛选、启停、报价可用性，而不是讲故事。

### 二、AI 解析器继续只做“录入辅助入口”，不回到首页主视图

- 当前方向建议明确固定：
  - 解析器放在 `新增 / 编辑` 页顶部
  - 产品中心只保留跳转入口
  - 解析结果必须先确认，再写回正式表单

- 这样做的好处：
  - 产品中心不被录入动作稀释
  - 解析器仍能服务新建与老产品修订
  - 用户心智会更清楚：
    - `产品中心` 是盘资产
    - `解析器` 是补资料

### 三、新建页和编辑页继续收成同一节奏

- 当前新建页和编辑页已经很接近一套统一结构：
  - 上方解析辅助
  - 下方分区式正式表单
  - 右侧录入摘要

- 这条方向建议保留。
- 下一步不建议重新拆成两套完全不同的页面语义。

- 建议统一为同一套心智：
  1. 先吸收标签图 / 文本
  2. 再确认行业、模板和售价
  3. 最后保存进正式产品库

### 四、详情页继续做“引用 / 检测 / 协作摘要”，不承载全量流程

- 当前详情页适合继续保留为：
  - 资产档案摘要
  - 文案与展示资料
  - 报价规则与可见范围
  - 最近引用记录
  - 关联检测
  - 协作动作

- 不建议这轮直接把详情页扩成：
  - 全量附件管理中心
  - 重型版本历史中心
  - 审批流主页面

- 原因：
  - 详情页的价值是快速判断“这条产品当前是否稳定可复用”。
  - 不是把所有子流程都塞进去。

### 五、真正要补的下一段，不是重做页面，而是补“待确认解析队列”

- 如果产品线要继续往 P1 目标靠近，最值得补的下一段是：
  - `待确认解析队列`

- 也就是把当前已经解析过、但还没正式写入或还需要人工复核的产品资料，形成一个明确队列。

- 这会比继续重画产品中心首页更有价值，因为它直接对应主目标里的：
  - `置信度`
  - `冲突对照`
  - `待确认队列`

- 所以当前建议节奏是：
  - `V1`：确认产品资产化结构成立
  - `V1.5`：补解析待确认队列
  - `V2`：再考虑版本历史、附件治理或批量维护
