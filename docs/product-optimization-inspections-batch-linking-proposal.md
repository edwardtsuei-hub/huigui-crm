# 检测管理页优化方案：待补关联批量处理

## 状态

- 当前状态：`正式批量补关联 V1 已接入，待验收`
- 对应主线文档：
  - `docs/product-optimization-master-plan.md`
- 当前正式验收网址：
  - `http://127.0.0.1:3202/inspections?queue=linking`

## 原问题

- 旧版检测工作台虽然已经能补客户和产品关联，但只支持单笔处理。
- 一旦出现一批待补关联的检测单，用户必须反复点开、逐条补、逐条保存。
- 这会让检测台更像“查看页”，而不是“处理台”。

## 已确认方案

- 保留当前 `左侧队列 + 右侧 Inspector` 结构，不重做整页。
- 第一版只在 `待补关联` 队列开启批量模式。
- 不新增后端批量接口，先沿用现有单笔更新接口逐条提交。
- 批量字段只补空缺，不覆盖已有客户或产品。

## 已落地内容

### 1. 已在待补关联队列加入批量模式入口

- 当前仅 `待补关联` 队列会出现 `开启批量处理`。
- 退出批量后，页面会回到原本单笔工作方式。

### 2. 已支持勾选、全选、清空

- 每张待补关联记录左侧增加选择按钮。
- 工具条支持：
  - `全选当前列表`
  - `清空已选`

### 3. 已接入批量草稿工具条

- 支持：
  - 批量补客户
  - 批量补产品
  - `套用到已选`
  - `提交已选`

### 4. 批量套用规则已做成保守模式

- 如果批量客户为空：不改客户草稿
- 如果批量产品为空：不改产品草稿
- 如果记录已经有客户 / 产品：不被批量值覆盖
- 如果有特殊情况：仍可在右侧 Inspector 单笔微调

### 5. 已补提交流程反馈

- 批量提交时会显示：
  - `处理中 x/y`
  - 成功数
  - 失败数
- 失败项会保留在已选列表，方便直接重试。

## 当前实现范围边界

- 这次没有做智能自动匹配。
- 这次没有新增真正的后端批量接口。
- 这次没有改成 Excel 式表格批量编辑。

## 当前相关代码位置

- 页面逻辑：
  - `apps/web/app/(dashboard)/inspections/page.tsx`
- 样式：
  - `apps/web/components/inspections/InspectionsWorkspacePreview.module.css`

## 下一步验收重点

- 批量模式是否足够稳，不影响原本单笔查看和编辑
- 勾选与提交路径是否比旧版明显更快
- “只补空缺不覆盖已有”的规则是否符合你们实际业务习惯
- 失败反馈是否足够清楚，能不能支持二次重试
