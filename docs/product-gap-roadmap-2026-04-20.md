# 2026-04-20 产品走查后的完善排期建议

## 范围

- 评估时间：`2026-04-20`
- 评估方式：
  - 本地启动 `@huigui/api`、`@huigui/web`
  - 使用真实种子数据登录并逐页走查
  - 按模块分批验证列表、详情、编辑、新建和跨模块跳转
- 本次重点走查范围：
  - 登录 / 首页 / 全局导航
  - 客户 / 产品 / 方案 / 报价
  - 订单 / 收款 / 发货 / 渠道结算
  - 检测 / 档案
  - 工作管理 / 日程 / 通知
  - 管理中心 / 设置

## 一句话判断

- 当前系统的主要问题已经不是“缺页面”，而是“高频业务闭环和批量处理能力还不够强”。
- 换句话说：单笔流程已基本可用，但一旦进入真实业务量和团队协作场景，效率、确认成本和误操作风险会明显上升。

## 排期原则

- `P0`：直接影响核心业务闭环、录入正确性、执行效率的项，建议优先进入最近 `1 ~ 2` 个迭代。
- `P1`：影响团队规模化使用和管理效率的项，建议紧接着进入后续 `1 ~ 2` 个迭代。
- `P2`：增强型能力和体验优化，可在主闭环稳定后推进。

## P0

### 1. 全局搜索升级为真实业务搜索

#### 当前问题

- 当前顶部“全域搜索”只能搜索工作台入口，不能搜索客户、报价、订单、产品等真实业务对象。
- 实测输入真实客户名 `张小兰` 时，只显示“没有匹配的工作台入口”。

#### 为什么优先

- 这是所有老数据回查、跨模块跳转和管理层抽查的最高频入口。
- 如果搜索弱，系统会变成大量页面的集合，而不是统一工作台。

#### 建议范围

- 搜索结果至少覆盖：
  - 客户
  - 报价
  - 订单
  - 产品
  - 检测单
  - 成员
- 结果按对象类型分组展示。
- 支持关键词直达详情页。
- 支持最近访问和热门对象。

#### 验收标准

- 输入客户名、报价单号、订单号、检测单号，均能返回真实业务结果。
- 回车默认进入最佳匹配结果，不再只跳工作台入口。
- 搜索结果里能看到对象类型、主标题、辅助说明。
- 无结果时提示“无匹配业务对象”，而不是“无工作台入口”。

### 2. 报价转订单改为确认式转单流程

#### 当前问题

- 报价详情页的“转为订单”当前是直接创建订单并跳转。
- 这对单笔 demo 很快，但对真实业务不安全，因为转单前仍可能缺：
  - 收货信息
  - 仓库
  - 渠道商
  - 履约备注
  - 收款策略

#### 为什么优先

- 订单一旦落库，就会影响后续收款、发货、渠道结算。
- 转单不确认，会把报价阶段的不完整数据直接带进履约链。

#### 建议范围

- 改成“转单确认抽屉”或“确认页”。
- 默认带入报价明细，但允许在转单前补齐订单头信息。
- 转单前显示风险提醒：
  - 缺收货信息
  - 缺渠道
  - 缺仓库
  - 金额未确认

#### 验收标准

- 点击“转为订单”后，不直接落库，先进入确认层。
- 未补齐关键字段时，不允许提交。
- 提交后生成订单，并保留“来源报价”关系。
- 已生成订单的报价，再次进入时展示“查看订单”，不重复生成。

### 3. 检测待补关联增加批量处理能力

#### 当前问题

- 首页和检测工作台都已经把“待补关联”抬到了高优先级，但实际处理方式仍偏单笔。
- 当前待补量达到两位数时，会明显拖慢整理速度。

#### 为什么优先

- 检测关联不补齐，后续客户、产品、档案、统计都不准确。
- 这是典型高频运营动作，必须支持批量。

#### 建议范围

- 在检测列表新增批量操作：
  - 批量指定客户
  - 批量指定产品
  - 批量标记稍后处理
  - 批量加入待办
- 对相似标题或相同实验室记录给出自动匹配建议。

#### 验收标准

- 运营可以一次选择多条检测记录完成关联。
- 批量保存后，列表计数和首页提醒即时刷新。
- 单条匹配不确定时，系统提示人工确认，不静默覆盖。
- 已关联记录不会继续出现在待补关联队列。

### 4. 报价中心与订单中心补齐批量处理工作台能力

#### 当前问题

- 当前两页的“指挥台感”已经有了，但仍偏单笔阅读型页面。
- 缺少真实业务量所需的批量操作和列表操作能力。

#### 为什么优先

- 管理员和销售主管通常不是处理一笔，而是同时推进多笔。
- 没有批量能力，团队会退回 Excel 或微信串联。

#### 建议范围

- 报价中心增加：
  - 多选
  - 批量导出
  - 批量发起审批
  - 批量标记已发送
  - 保存筛选视图
- 订单中心增加：
  - 多选
  - 批量登记状态
  - 批量发货准备
  - 批量催收
  - 按负责人 / 渠道 / 状态保存视图

#### 验收标准

- 报价和订单列表支持多选。
- 至少 `3` 个高频批量动作可用。
- 批量动作后有结果反馈，成功与失败分开提示。
- 刷新页面后，保存的视图还能复用。

### 5. 行业 / 服务 / 养殖报价从“共用页面”升级为“业务化页面”

#### 当前问题

- 目前这三条新建路径都直接复用通用报价页。
- 对用户来说，入口不同，但到达后体验没有差异。

#### 为什么优先

- 这会削弱“业务类型”的意义。
- 用户无法感知自己当前是在做行业报价、服务报价还是养殖报价。

#### 建议范围

- 保持底层共用，但在页面层做业务分化：
  - 页面标题
  - 默认文案
  - 默认筛选产品范围
  - 必填字段
  - 右侧摘要说明
  - 导出模板

#### 验收标准

- 三条入口进入后，标题、说明和默认字段明显不同。
- 不同行业默认只展示本行业适用产品或模板。
- 导出结果能体现报价类型差异。

## P1

### 1. 客户池治理能力增强

#### 建议范围

- 客户去重与合并
- 跟进超时提醒与 SLA
- 负责人负载视图
- 沉默客户和高意向客户自动队列

#### 验收标准

- 可以识别高疑似重复客户。
- 能看到超期未跟进客户清单。
- 管理员可以按负责人查看客户负载分布。

### 2. 产品解析能力从“辅助录入”升级为“半自动建档”

#### 建议范围

- 字段置信度
- 来源字段高亮
- 冲突字段对照
- 批量导入
- 解析后待确认队列

#### 验收标准

- 用户能看见哪些字段来自 AI 建议，哪些来自已有表单。
- 冲突字段不被静默覆盖。
- 支持连续处理多条产品录入任务。

### 3. 档案中心与业务主链自动关联

#### 建议范围

- 客户 / 报价 / 订单 / 检测自动归档
- 资料夹自动生成
- 附件版本管理
- 待审核队列

#### 验收标准

- 从报价、订单、检测上传的文件能自动带上业务关联。
- 用户在详情页可直接看到相关档案。
- 同名新版本可形成版本链，而不是新增孤立文件。

### 4. 工作管理补齐团队推进闭环

#### 建议范围

- 一键催交周报 / 月目标
- 未提交原因
- 团队差异视图
- 从周报 / 目标直接派生提醒和待办

#### 验收标准

- 管理者能快速看见谁未交、谁风险高、谁目标空泛。
- 至少支持一次性提醒未提交成员。

### 5. 通知与日程支持“处理动作”而不只是“查看动作”

#### 建议范围

- 稍后提醒
- 转待办
- 批量已读
- 批量分派
- 回写来源对象状态

#### 验收标准

- 用户不离开通知和日程页，也能完成主要处理动作。
- 处理后来源对象状态同步更新。

### 6. 权限配置补齐变更安全性

#### 建议范围

- 权限变更 diff
- 影响面预览
- 保存前确认
- 角色复制

#### 验收标准

- 管理员保存角色前能看到本次变更影响哪些菜单、页面、动作。
- 支持从现有角色复制出新角色。

## P2

### 1. 首页与工作台进一步个性化

- 按角色切换首页卡片结构
- 支持自定义常用入口
- 支持拖拽排序和个人固定视图

### 2. 经营分析与趋势视图

- 报价转单率
- 客户阶段转化率
- 检测回款与交付周期
- 渠道利润趋势

### 3. 自动化提醒策略

- 按客户状态自动催跟进
- 按报价状态自动催审批
- 按订单状态自动催收款 / 发货
- 按检测状态自动催结果

### 4. 移动端 / 低分辨率适配进一步收口

- 列表密度切换
- 抽屉和固定侧栏在窄屏下重构
- 高密度表单在移动端优化输入路径

## 建议迭代拆分

### 迭代 1

- 全局搜索真实业务化
- 报价转订单确认流
- 检测批量补关联

### 迭代 2

- 报价中心批量动作
- 订单中心批量动作
- 行业 / 服务 / 养殖报价业务化页面

### 迭代 3

- 客户池治理
- 档案自动归档
- 工作管理团队闭环

### 迭代 4

- 通知 / 日程处理动作
- 权限变更安全性
- 首页个性化与分析增强

## 总体验收口径

- 每条主链都要满足：`能进入`、`能处理`、`能回写`、`能回查`。
- 每个高频工作台都要满足：`支持批量`、`支持保存视图`、`支持回到来源对象`。
- 每个跨模块动作都要满足：`带上下文进入`，不要求用户重复填写已知信息。
- 每个关键动作都要满足：`有前置确认`、`有结果反馈`、`有失败提示`。

## 最终建议

- 如果只做一轮优先级最高的产品补强，建议先只盯住三件事：
  - 把搜索做成真实业务搜索
  - 把报价转订单做成确认式闭环
  - 把检测待补关联做成批量工作台

- 这三件事一旦补上，系统会从“模块完整”明显提升到“团队真能高频用”。
